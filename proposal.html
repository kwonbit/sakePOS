01 / OVERVIEW

프로젝트 목표

사케를 잘 모르는 고객도 몇 가지 질문만으로 취향과 음식, 예산에 맞는 사케를 찾고, 매장 운영자는 개발자 도움 없이 상품 정보를 최신 상태로 유지하는 것이 핵심입니다.

CUSTOMER EXPERIENCE

쉽게 발견하는 사케

검색·필터·상세 정보와 설문형 추천으로 고객의 선택을 돕습니다.

STORE OPERATION

직접 관리하는 상품

150~200종의 상품, 가격, 재고와 판매 상태를 관리자 화면에서 관리합니다.

FUTURE READY

확장 가능한 구조

향후 POS, 판매 분석, 회원 및 온라인 주문 기능을 연결할 수 있게 설계합니다.

02 / TECHNOLOGY

추천 개발 방식과 기술

노코드 플랫폼에 종속되지 않는 범용 웹 기술을 사용합니다. 소스코드와 데이터베이스를 발주자 계정으로 관리해 향후 다른 개발자도 유지보수할 수 있도록 합니다.

FRONTEND

React + TypeScript

고객용 반응형 화면과 관리자 화면을 하나의 프로젝트로 구성합니다. iPad와 모바일에 최적화하고 재사용 가능한 UI 컴포넌트로 개발합니다.

DATABASE

Supabase + PostgreSQL

상품, 가격, 재고, 판매 상태, 추천 태그를 관계형 DB로 관리합니다. 관리자 인증과 데이터 접근 권한을 구성합니다.

DEPLOYMENT

GitHub + Cloudflare Pages

소스코드를 GitHub에서 버전 관리하고 웹앱을 배포합니다. Supabase 프로젝트는 발주자 명의 계정으로 운영합니다.

03 / SCOPE

1차 개발 범위

초기 오픈에 필요한 고객용 기능과 운영자 기능을 우선 구현합니다.

상품 DB: 제품명·일본어명·사진·양조장·지역·종류·수입사
상세 정보: 사용쌀·정미율·도수·설명·테이스팅 노트
가격 관리: 매장용 가격과 소매 가격 분리 관리
재고 관리: 수량 변경 및 고객 화면 실시간 반영
판매 상태: 판매중·품절·재입고 예정·시즌 종료·비노출
검색: 제품명·지역·종류·수입사 검색 및 필터
맛 분석: 단맛·드라이·산미·감칠맛·바디·향 시각화
추천: 취향·음식·선물용 설문 기반 3~5종 추천
QR 연결: 상품별 고유 상세페이지 주소 제공
반응형: 매장 iPad와 고객 스마트폰 대응
운영 원칙
상품은 삭제하지 않고 판매 상태로 노출 여부를 관리합니다. 재고가 0이면 품절로 자동 전환하거나 품절 표시를 적용합니다. 고객 화면에는 매장용·소매용 가격 중 선택된 한 가지 가격만 표시합니다.
04 / RECOMMEND

설문형 사케 추천 시스템

초기 버전은 외부 AI API 없이 점수·태그·가중치 방식으로 구현합니다. 운영자가 입력한 맛 성향 데이터와 추천 태그를 활용해 현재 구매 가능한 상품을 추천합니다.

01 · TASTE

내 취향에 맞는 사케

예산, 단맛·드라이·산미, 향과 바디 선호, 사케 경험 수준을 반영합니다.

02 · FOOD PAIRING

음식과 어울리는 사케

함께 먹을 음식과 선호 스타일을 기준으로 조화 점수를 계산합니다.

03 · GIFT

선물용 사케

예산과 선물 상황, 추천 태그를 조합해 적합한 상품을 제안합니다.

추천 대상은 판매 가능한 상품으로 제한하며, 점수 상위 3~5종과 추천 이유를 함께 보여줍니다. 질문과 가중치는 추후 관리자 설정으로 확장할 수 있도록 구조화합니다.

05 / SCHEDULE

예상 개발 일정

전체 약 6~8주를 기준으로 진행하며, 상품 데이터 준비와 검수 일정에 따라 세부 일정은 조정합니다.

WEEK 01기획·설계화면 구조, UI 방향, DB 설계, 프로젝트 세팅
WEEK 02관리자 기반상품 DB, 관리자 인증, 상품 등록·수정
WEEK 03고객 화면목록, 검색·필터, 상품 상세
WEEK 04운영 기능재고·판매 상태, 가격 표시 모드
WEEK 05추천 기능설문, 태그·가중치 추천 로직
WEEK 06–08검수·오픈반응형 테스트, 데이터 적용, 배포·교육
